# Open work — update-studio-kh

Only open work for this repo. Update in the same commit whenever work starts, changes, or finishes.
Keep this file public-safe: no home paths, no hostnames or network addresses, no secrets.
History belongs in git log and receipts; failure patterns belong to the plugin's issue directory.

- [ ] **A published card cannot be rolled back** — `khu feed` can move a row forward only; when a build is found dead after a pass, the remedies are a new version or a hand-edited feed, and the second is forbidden. Add a per-run `--pin <app>=<version>:<reason>` to the producer that resolves that exact published, non-draft release, proves its asset downloads anonymously, takes its words and release body, refuses an unknown app or a missing reason, and prints `pinned: <app> <version> (<reason>)`. **Next:** land it in `Sources/KHUpdaterCore/FeedGenerator.swift` + `Sources/khu/main.swift` with tests for a valid older pin, an undownloadable asset and a blank reason.
- [ ] **A moving `released` field is silent** — a release re-created with its repository carries the same bytes under a new `published_at`, and nothing in the run report says so; an un-drafted release moving `released` is the opposite case and must never look the same. Compare a same-version row's `released` and name the cause: a note when `sha256`, `bytes` and the url filename are unchanged (naming a recreated repo where the repo's own creation date proves it), a refusal when any artifact field differs. **Next:** add the comparison to `FeedGenerator` with both tests.
- [ ] **The run report does not check a tag against its commit** — `app-meta.json` is read at the tag, so a tag cut before the file landed serves the previous version silently, and a release can carry the right asset for the wrong tree. Name each row's tag commit, and refuse when a release body's `GATE PASS` sha disagrees with the commit the tag resolves to. **Next:** resolve the tag ref (following an annotated tag) in `FeedGenerator` and print `tag: <app> <tag> -> <commit>` per row, with tests for a peeled annotated tag and a mismatch refusal.
- [ ] **A fixture can forget an address and still compile** — `FeedPublisher.publish`'s `url:` has a default, so a test helper that never sets it compiles and fails at run time; the production path legitimately passes nothing. Split it into a production entry point with no address parameter at all and a fixture entry point whose address is required and non-optional. **Next:** split `Publish.publish`, update `main.swift` and the test callers, and prove a missing address cannot compile.
- [ ] **The app list says nothing about the last check** — a Mac on the public feed can fail every check and show nothing: the time, the outcome and the reason when it failed are not on the page, and a failed install path reads as silence. Show the last check per app from the app's own record, never from a publisher. **Next:** read the helper's last-run record into the page state and render one line per app with the time and, on failure, the reason.
